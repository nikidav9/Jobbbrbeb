This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Язык работы — русский: так написан код, документация и переписка с владельцем.

## Что это за проект

Поиск постоянной работы в Москве. Работник листает карточки свайпом, откликается
и общается в чате. Все вакансии свои: работодатели публикуют их сами. Подработка
(смены) закрыта 17.09.2026 — старые смены в базе живут, новых не создать.

Карта репозитория — `docs/MAP.md`. **Начинай поиск оттуда, а не с обхода файлов.**

## Приложение уже выложено. Это меняет цену ошибки

RuStore, порядка 500 живых пользователей, пакет `com.nikidav23.onspaceapp`.

**Мерж в `main` сам выкатывает OTA-обновление** этим людям:
`.github/workflows/eas-update.yml` срабатывает на push в `main` (кроме `docs/**`
и `*.md`) и публикует в канал `production`.

Отсюда три запрета, каждый из которых ломает установленное приложение:

- не менять `version` в `app.json` (там `runtimeVersion: {policy: "appVersion"}`,
  и новая версия отрежет обновление от старого бинарника);
- не добавлять нативные модули — в собранном бинарнике их нет, JS-бандл с ними
  упадёт при запуске;
- не писать в `main` напрямую: только ветка → PR → зелёный CI → мерж.

## Архитектура: то, чего не видно из одного файла

**Клиент ходит на сервер одной дверью.** `services/db.ts` шлёт
`POST /api/db.php` с телом `{fn, args}` — это RPC, а не REST. Добавляя серверную
функцию, правишь обе стороны: `services/db.ts` и `php-proxy/db.php`.

**Права живут в одном месте, и это не клиент.** В начале `php-proxy/db.php`
стоят списки: `$publicFns` (можно без входа), `$adminFns`, `$selfArgFns`
(позиция аргумента, который обязан совпасть с владельцем сессии). Функция, не
попавшая ни в один список, требует авторизации. Забыть про `$selfArgFns` —
значит отдать чужие данные любому вошедшему.

**Три поверхности одного кода.** Приложение, сайт и мини-приложение в телеграме
собираются из одного `app/`. Поэтому веб — рабочая поверхность, а не побочная:
`expo export --platform web` входит в обязательные проверки.

**Jupiter — отдельный агент, не часть приложения.** `jupiter/` подаёт отклики на
внешних карьерных сайтах: свой HTTP-клиент, cookie jar, разбор HTML и форм,
политика переходов, отправка и проверка успеха. Ни Playwright, ни Selenium, ни
Chromium — и возвращать их нельзя. Инварианты, которые нельзя снимать:
`read_only=True` блокирует отправку на уровне движка; CAPTCHA не обходится;
неизвестные факты о кандидате не выдумываются. Подробности — `jupiter/README.md`
и раздел про Jupiter в `docs/MAP.md`.

**Свежесть карты обязательна.** Изменил устройство части проекта — поправь
строку в `docs/MAP.md` тем же коммитом. Отставшая карта хуже её отсутствия: она
уводит не туда с полной уверенностью.

## Всегда прожимать по методу grill-me (включено пользователем, режим «на каждый запрос»)

Перед выполнением **любого** запроса применяй подход скилла `grilling` / grill-me —
не только когда его вызывают явно через `/grilling`:

- Не бросайся сразу делать. Сначала прожми запрос уточняющими вопросами.
- Задавай вопросы **строго по одному**, дожидаясь ответа на каждый, и к каждому
  давай свой рекомендованный ответ.
- Иди по дереву решений, разрешая зависимости одну за другой, пока не достигнете
  общего понимания.
- **Факты**, которые можно узнать из кода, базы или окружения, — выясняй сам
  (не спрашивай). Спрашивай только **решения**, которые за пользователем.
- Не начинай реализацию, пока пользователь не подтвердит, что понимание общее.

Единственное послабление: если запрос абсолютно однозначен и уточнять реально
нечего (например «задеплой», «покажи статус», «отправь пост, что мы согласовали»),
и всё, что нужно, я могу проверить сам — выполняй сразу, без искусственных вопросов.

Как выключить/сузить: отредактировать или удалить этот раздел в `CLAUDE.md`.

## Чем это принуждается

Правила ниже — не пожелания: их подмешивает харнесс, а не моя память.

| Когда | Что происходит | Чем |
|---|---|---|
| Перед **каждым** запросом | в контекст подмешиваются grill-me, подбор скилла, экономия токенов и требование проверять свою работу | `UserPromptSubmit` → `.claude/hooks/before-request.sh` |
| Перед первой правкой файла в сессии | напоминание про скиллы у самого момента правки | `PreToolUse` на `Write\|Edit` → `.claude/hooks/skill-check.sh` |

Почему два, а не один: подсказка из начала разговора в длинном ходе вытесняется
ровно тогда, когда начинается настоящая работа. Второй хук ловит этот момент.

Настройка — `.claude/settings.json`, посмотреть и выключить — командой `/hooks`.
Текст первого хука намеренно короткий: он идёт с каждым запросом, и лишние
полсотни слов там стоят дороже, чем кажется.

## Скиллы: проверять перед каждым изменением

В `.claude/skills/` лежит библиотека (сейчас 870+ штук). Она бесполезна, если о ней не
вспоминать. Поэтому правило жёсткое:

**Перед любым изменением — сначала вопрос себе: какой скилл здесь поможет?**
Нашёл — вызови его через `Skill` и работай по нему. Не нашёл — работай как обычно,
но если задача такого рода повторится, заведи новый скилл через `skill-creator`.

Смысл в том, чтобы скиллы применялись, а не лежали.

## Плагины: ставим и пользуемся

Четыре внешних плагина обязательны к установке и к использованию — не «по желанию».
Ставятся **один раз на своей машине**: в облачной сессии плагины не живут, контейнер
одноразовый, поэтому `/plugin` выполняет пользователь, а не агент.

### ponytail — ленивый сеньор

```
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
```

Заставляет обосновывать каждую строку до того, как она написана: YAGNI, сначала
стандартная библиотека, одна строка вместо пятидесяти. Правила подмешиваются
перед каждым ходом и передаются в сабагентов.

**Когда обязателен:** всегда. Если решение тянет новую зависимость или новый слой
абстракции — сначала объясни, почему без них нельзя.

### graphify — граф кода

```
pip install graphifyy && graphify install
graphify hook install
```

Это **не** `/plugin`, а pip-пакет — ставится отдельно. Разбирает код, схемы SQL,
конфиги и документы в запрашиваемый граф: локальный AST-разбор, без векторной базы.
`graphify install` дописывает директиву в `CLAUDE.md` и ставит PreToolUse-хук, так что
граф спрашивается **до** поиска по файлам. `graphify hook install` — post-commit хук,
граф пересобирается после каждого коммита.

**Когда обязателен:** любой вопрос «где это лежит» и «что на это завязано» — сначала
граф, только потом `grep`. Это прямое продолжение раздела «Экономия токенов»: на
`feed.tsx` в 2600 строк и `db.php` в 5900+ граф дешевле полнотекстового поиска.

### agent-skills — ещё один набор скиллов

```
/plugin marketplace add alirezarezvani/claude-skills
/plugin install engineering-skills@claude-code-skills
```

24 инженерных скилла. Точное имя в списке уточнить при установке — маркетплейсов с
похожим названием несколько, ставить надо тот, где ровно 24 скилла.

**Когда обязателен:** по тем же правилам, что и `.claude/skills/` — см. раздел выше.
Приоритет у своих скиллов проекта: они написаны под JobToo, внешние — общие.

### omniroute — шлюз к другим провайдерам

**Не ставим — решение принято владельцем проекта.** Это не помощник, а подмена
бэкенда: плагин переписывает конфиг Claude Code так, чтобы запросы шли через сторонний
шлюз к чужим провайдерам моделей. Для JobToo это означает, что исходники и переписка
уходят третьей стороне — а у нас персональные данные под 152-ФЗ, публичный репозиторий
и живые токены (бот, Метрика). Экономия на токенах этого не стоит.
Если кто-то из агентов увидит omniroute в конфиге — это не наша установка, сообщить.

### Проверить, что всё на месте

```
/plugin                      # ponytail и agent-skills должны быть в списке
graphify status              # граф собран и свежий
```

Плагина нет — не делай вид, что он есть: скажи об этом прямо и работай без него.

## Текущий режим работы

Telegram выведен из контура: беседой не пользуемся, общение идёт в терминале
сессии. Работа идёт последовательными срезами: ветка от свежего `main` → PR →
зелёный CI → мерж. Напрямую в `main` не пишет никто.

Порядок работы — `docs/круг-работы.md`, очередь задач — `docs/очередь-задач.md`.
Там же записаны два правила, добытые ошибками: проверять работу целиком, а не по
отчёту, и судить о живости процесса по свежести отметки, а не по `pgrep`.
