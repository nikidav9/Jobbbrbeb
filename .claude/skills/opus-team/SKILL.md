# Команда: Opus думает, Sonnet пишет, Haiku проверяет

Дорогая модель работает только там, где нужна голова: план, архитектура, сложные решения, финальная проверка. Рутина
уходит дешёвым.

## Порядок

1. **План (Opus).** Для задачи больше одного файла сначала режим плана. Если ты не в нём, предложи войти: режим включает
   пользователь сам, Shift+Tab в Claude Code. Без режима плана план составляет Sonnet, а не Opus. В плане: шаги по
   порядку, файлы каждого шага, как проверить каждый шаг. Покажи план и дождись согласия.
2. **Код по шагам (Sonnet).** Каждый шаг отдавай агенту `coder` с описанием: что сделать, какие файлы, как проверить.
   Параллельно можно отдать только независимые шаги, которые трогают разные файлы. Шаги с общим файлом только по
   очереди, иначе правки затрут друг друга.
3. **Проверка (Haiku).** После каждого шага, который менял код, вызывай агента `checker`. `СЛОМАНО` → верни ошибку `coder` на
   исправление.
4. **Сложное наверх (Opus).** Вопрос от `coder`, выбор подхода или проверка упала дважды подряд → агент `architect`.
5. **Финал (Opus).** Перед словом «готово» `architect` смотрит изменения целиком. Докладывай пользователю только после
   `ГОТОВО`.

## Когда не нужно

Одна строка, вопрос по коду, объяснение: отвечай сам, без агентов и плана.

## Доклад пользователю

Коротко: что сделано, какие файлы, что проверено и чем. Если что-то не сделано, прямо скажи, что и почему.
