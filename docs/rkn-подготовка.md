## 2. Трансграничная передача — фактические потоки и поля формы РКН

После переезда основная база и файлы хранятся в РФ. В текущем пользовательском
контуре трансграничная передача связана только с push/web-push транспортом.

| Канал / получатель | Что реально передаётся | Государство |
|---|---|---|
| **Expo Push / 650 Industries, Inc.** | Expo push-токен и одинаковый нейтральный payload «JobToo / У вас новое уведомление»; без user_id, chat_id, vacancy_id, типа события и содержания события | **США** |
| **Apple APNs / Apple Inc.** | платформенная доставка iOS push: provider token и тот же нейтральный payload | **США** |
| **Google FCM / Google LLC** | платформенная доставка Android push: provider token и тот же нейтральный payload | **США** |
| **Web Push** | endpoint подписки, `p256dh`, `auth`, заголовок/текст уведомления; конкретный провайдер зависит от браузера | **США** для используемой инфраструктуры Google/Apple/Mozilla |

### Что код реально отправляет

1. **Native push через Expo → APNs/FCM.** Текущая сборка получает
   `ExpoPushToken`, а сервер отправляет его в Expo Push Service. Expo уже
   маршрутизирует уведомление в APNs или FCM. Это важно: наличие
   `google-services.json` не означает, что сервер JobToo сейчас отправляет
   Android-push напрямую в Firebase.
2. Любой **нативный** Expo push перед отправкой сворачивается до одинакового
   нейтрального сигнала «JobToo / У вас новое уведомление». В нативный payload
   не попадают user_id, chat_id, vacancy_id, тип события, имя или содержание
   события. Детали остаются в `jm_notifications` в российской базе.
3. Expo push-токен хранится в `jm_users.push_token` не открытым текстом, а в
   AES-256-GCM ciphertext с keyed fingerprint для поиска дублей. Отдельный ключ
   лежит только на московском сервере; plaintext появляется непосредственно
   перед вызовом Expo API, потому что без исходного provider token доставка
   технически невозможна.
4. **Web Push** хранит endpoint, `p256dh` и `auth` в российской базе и
   передаёт уведомление через push-службу соответствующего браузера. Этот
   канал пока имеет отдельный payload и не смешивается с нативным Expo push.
5. Файлы фото профиля, фотографии из чата и голосовые файлы через эти каналы
   не отправляются.

### Что ставить в отдельном уведомлении о трансграничной передаче

**Правовое основание:** отметить только
**«наличие согласия субъекта персональных данных на обработку его персональных
данных»**. Push/web-push подключаются добровольно; при отказе JobToo продолжает
работать с внутренним колокольчиком.

**Категории передаваемых ПДн — отмечать:**
- **«иные персональные данные»** — вписать:
  «provider token нативного push; web-push endpoint, p256dh и auth;
  технические данные маршрутизации и доставки уведомлений; для native push —
  нейтральный служебный payload без идентификаторов пользователя/события; для
  web-push — служебный payload и текст уведомления».

**Не отмечать как текущую трансграничную передачу:**
`фамилия, имя, отчество`, номер телефона, возраст,
email, адреса, исходные PDF-резюме, структурированные сведения резюме (должность,
зарплата, опыт, образование, навыки и т. п.), СНИЛС, ИНН пользователя,
документы, банковские реквизиты, фото-видео изображение лица, данные голоса,
сведения метрических программ, специальные категории ПДн и биометрические ПДн.
Эти данные остаются в РФ и не являются частью текущего push/web-push потока.

**Категории субъектов — отмечать:**
- **Соискатели**;
- **Представители контрагентов** — зарегистрированные представители
  работодателей/заказчиков;
- **Субъект персональных данных, предоставивший согласие на трансграничную
  передачу персональных данных**;
- **Контрагенты** — только если конкретный аккаунт работодателя принадлежит
  ИП/самозанятому/физическому лицу, действующему от собственного имени.

Посетителей сайта только из-за Метрики не отмечать: Яндекс.Метрика не является
описанным зарубежным каналом. Web-push относится к авторизованным пользователям,
которые отдельно дали разрешение на уведомления.

**Иностранное государство для текущей схемы:**
- **Соединённые Штаты Америки** — Expo, Apple, Google и используемые
  браузерные push-провайдеры.
