# Карта репозитория JobToo

Оглавление проекта: где что лежит и куда идти за чем. Нужна, чтобы не перечитывать
одни и те же файлы в каждой сессии — поиск начинается отсюда, а не с обхода репозитория.

**Правило сопровождения:** изменил устройство части проекта — поправь здесь строку
тем же коммитом. Карта, отставшая от кода, хуже её отсутствия: она уводит не туда
с полной уверенностью.

## Что это за проект

Приложение подработки и постоянной работы: смены на складах Москвы и вакансии.
Работник листает карточки свайпом, откликается, общается в чате и выходит на смену.
Часть вакансий своя (работодатели публикуют сами), часть приходит от партнёров.

Клиент — React Native на Expo SDK 53, маршрутизация expo-router по файлам.
Работает как приложение, как сайт и как мини-приложение в телеграме.
Сервер — PHP-прокси перед базой. Панель управления — отдельное приложение на Next.js.

## Верхний уровень

| Каталог | Что внутри |
|---|---|
| `app/` | Экраны приложения. Имя файла = адрес (expo-router). `(tabs)/` — вкладки |
| `components/` | Общие компоненты. `ui/` — мелкие, `feature/` — крупные с логикой |
| `services/` | Работа с данными и внешним миром. Точка входа к серверу — `db.ts` |
| `contexts/` | Общее состояние. Главный — `AppContext.tsx` |
| `hooks/` | Хуки. `useApp`, `useSwipeDeck` (свайп карточек) |
| `constants/` | Типы, тема, юридические тексты, метро, справочники |
| `php-proxy/` | Серверная часть: обработчик запросов, сборщики партнёрских вакансий, бот |
| `supabase/migrations/` | Миграции базы, 66 штук, применяются по порядку номеров |
| `dashboard/` | Панель управления на Next.js, 29 разделов аналитики |
| `infra/` | Развёртывание: `bootstrap.sh` (сервер тянет обновления), nginx, docker |
| `docs/` | Документация, включая эту карту |
| `.claude/skills/` | Библиотека скиллов, 870+ |
| `tests/` | Тесты на node:test, запуск `npm test` |

## Куда идти за чем

### Лента и свайп
- `app/(tabs)/feed.tsx` — **4800 строк, целиком не читать.** Две колоды: смены
  (`WorkerFeed`) и постоянная работа (`WorkerPermMode`). Ищи `grep`-ом по имени.
- `hooks/useSwipeDeck.ts` — физика свайпа, общая для обеих колод.
  Жест на gesture-handler, значения на Reanimated, всё на потоке интерфейса.
- Внутри карточки **прокрутки нет** — это решение, а не упущение: два жеста на одной
  площади дерутся, и карточка улетала от попытки полистать.

### Подробности вакансии
Один макет на три вида, собран из общих кусков:
- `components/feature/VacancyDetailHead.tsx` — шапка: знак компании, «40 минут назад», чипы
- `components/feature/VacancyContacts.tsx` — раздел «Контакты», скрыт до входа
- `components/feature/VacancyDetailModal.tsx` — экран смены
- `components/feature/ExternalVacancyDetail.tsx` — экран партнёрской вакансии
- `app/perm-vacancy-detail.tsx` — экран постоянной вакансии (есть и как ссылка из телеграма)

### Страницы для поисковиков

Приложение рисует вакансии в браузере, роботу показывать нечего. Рядом с прокси
живёт тонкий серверный слой — приложение он не трогает:

- `php-proxy/vacancy_page.php` — страница одной своей вакансии: настоящий HTML,
  разметка `JobPosting`, канонический адрес. Подключается тестом как библиотека
  через константу `VACANCY_PAGE_LIB_ONLY`.
- `php-proxy/sitemap.php` — карта сайта, собираемая из базы. Статического
  `public/sitemap.xml` больше нет.
- `php-proxy/vacancy_url.php` — одно правило годности идентификатора для адреса,
  общее для страницы и карты: иначе карта опубликует то, что страница не откроет.
- Маршруты `/v/<id>` и `/s/<id>` в `infra/nginx-site.conf`. Стоят **выше** правила
  о путях с расширением: идентификатор может содержать точку.
- `php-proxy/landing_page.php` — сводные страницы «работа комплектовщиком в Москве»
  и она же по станции. Маршруты `/rabota/<профессия>` и `/rabota/<профессия>/<станция>`.
  Порог `LP_MIN`: меньше пяти вакансий — страницы нет, тонкая страница понижает
  весь сайт. Перечень существующих страниц отдаёт `lp_index()`, им же пользуется
  карта сайта.
- Отдельных страниц партнёрских вакансий нет намеренно — их текст совпадает с
  hh.ru. Но в сводках они участвуют: сводка это наш собственный счёт, а не копия
  чужого текста.

### Связь с сервером
- `services/db.ts` (~2000 строк) — все вызовы. Обращение по схеме `fn` + `args`.
- `php-proxy/db.php` (**5200 строк, целиком не читать**) — обработчик. Функции ищи
  `grep -n "case 'имяФункции'"`.
- Адрес сервера на вебе — origin текущей страницы, на телефоне — из окружения.

### Партнёрские источники
- `php-proxy/headhunter.php`, `superjob.php`, `trudvsem.php`, `arbihunter.php` — сборщики.
  Ходят в **официальные интерфейсы** (`api.hh.ru`, `api.superjob.ru`,
  `opendata.trudvsem.ru`), а не парсят страницы.
- `php-proxy/ingest.php` — приём и склейка дублей.
- `php-proxy/ext_health.php` — молчание источников и перекос в один. Чистые
  функции, подключается из `db.php`; тревога уходит в суточный отчёт
  `cronDailyReport`. Проверка — `tests/ext_health_test.php`.
- `php-proxy/career.php` + `career_feed.php` — карьерные страницы работодателей:
  разбор разметки `JobPosting` прямо с сайта работодателя, без посредника.
  Адреса страниц — в `connector_config.pages` источника, задаются в панели.
  Источник заведён **выключенным** (миграция `063`). Проверки —
  `tests/career_feed_test.php` и `tests/career_infra_test.py`.
- `php-proxy/safe_url.php` — одно правило на всех, куда сборщику можно ходить.
  Своей копии не заводить: см. заголовок файла.
- Список источников — в миграциях `054`–`058` и `063`.

### Приглашения (реферальная программа)
- `php-proxy/referral.php` — чистые правила: код приглашения и «за что платим».
  **Вознаграждение только за выход на смену** (`outcome = 'worked'`), никогда за
  отклик — урок Jobr из плана развития.
- Связь пишется в `jm_users.invited_by` **сервером** при регистрации по коду из
  второго довода `dbUpsertUser`; клиент это поле не правит.
- Начисления — `jm_referral_rewards` (миграция `064`), журнал событий, а не
  счёт. Заводятся из `jt_referral_on_outcome` в `db.php`.
- Сумма в коде не зашита: назначает владелец, запись ждёт со статусом `pending`.
- Проверка — `tests/referral_test.php`.

### Безопасность и сессии
- **Смену закрывает её сторона.** `jt_shift_party` в `db.php`: итог смены ставит
  работодатель, старые `dbConfirmShift`/`dbCancelShift` — любая из двух сторон.
  Владелец тут не довод запроса, а поле в строке, поэтому в `$selfArgFns` такие
  операции не попадают и нуждаются в своей проверке. Тест —
  `tests/shift_authz_test.php`.
- `services/db.ts`: `IS_NATIVE = true` **всегда**, Supabase из браузеров в РФ
  недоступен. Ветки с прямым обращением к Supabase — мёртвый код, живой путь
  один: `db.php`. Искать защиту в политиках RLS для них бессмысленно.
- Токен сессии: выдаётся `jt_session_issue`, проверяется `jt_session_claims` в `db.php`.
  Отзыв — по полю `sessions_valid_from` (миграция `062`).
- Заголовки безопасности — `infra/nginx-site.conf`.
- Юридические тексты — `constants/legal.ts`. Правка `dataPolicy` **не** вызывает
  повторного согласия: ключа нет в `LEGAL_KEYS`, это сделано намеренно.

### Телеграм
- `php-proxy/tg.php` — вебхук бота приложения `@JobToo_bot`.
- `php-proxy/bot_brain.php` — ответы бота.
- `php-proxy/tgtool.php` — служебная отправка в общую группу. Адрес группы зашит
  числом намеренно: пропуск лежит в открытом коде.
- Мост к Codex (PR #62) и рабочая беседа в телеграме **выведены из контура 13.09**
  решением владельца. Механика описана в истории PR, но не используется: работу
  ведёт Claude один, общение — в терминале сессии. Продуктового бота это не
  касается: уведомления людям и автоматические отчёты идут как шли.
- `lib/telegram.ts` — мини-приложение: ссылки `startapp`, настройка окна.

### Панель управления
`dashboard/` — Next.js, TailAdmin. 29 разделов: воронка, когорты, активность, гео,
вовлечённость, качество, спящие, источники, матчинг. Запросы — `dashboard/lib/queries.ts`.
Выкладка — отдельная, через релизы GitHub; сервер тянет их сам.

### Выкладка
- Пуш в `main` запускает: `ci.yml`, `deploy-regru.yml` (сайт на московский сервер),
  `eas-update.yml` (обновление приложения по воздуху).
- `public/robots.txt`, `public/sitemap.xml` — поисковые правила и карта только
  существующих публичных страниц; файловые URL без файла получают 404 в nginx.
- `infra/bootstrap.sh` — сервер раз в минуту проверяет обновления и тянет их сам.
- Регулярные задачи: `evening-digest.yml` (16:00 UTC), `daily-nudges.yml` (07:00),
  `partner-monthly-report.yml`, `site-availability.yml` (каждые 5 минут).

## Грабли, на которые уже наступали

- **`app/(tabs)/feed.tsx` и `php-proxy/db.php` слишком велики для чтения целиком.**
  Всегда `grep` по имени, потом `sed -n 'N,Mp'`.
- **На вебе после перетаскивания приходит `click`** — нажатие срабатывает вслед за
  свайпом. Лечится признаком «только что был свайп».
- **`curl` в GitHub без `-L`** врёт после переименования репозитория: ответ `301`
  выглядит как отсутствие данных.
- **Заголовки nginx внутри `location` заменяют серверные целиком**, а не дополняют.
- **`.expo/types/router.d.ts`** — временный артефакт. Если после запуска dev-сервера
  `tsc` ругается на маршруты, удали каталог `.expo/types`.
- **Метрика стоит, но её данные никуда не забираются** — счётчик `109805381`.
