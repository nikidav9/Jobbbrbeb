## Шаги владельца по порядку

### 1. Firebase (пуши на Android)
**Сделано 03.10.2026:** Android-приложение `com.jobtoo` добавлено в проект
`jobtoo-266b7`, `google-services.json` лежит в репозитории (в нём оба пакета —
новый и старый). Остаётся пункт 3 ниже: ключ сервисного аккаунта в EAS.

Как это делалось:
1. Консоль Firebase, проект `jobtoo-266b7` → «Добавить приложение» → Android →
   пакет **`com.jobtoo`**.
2. Скачать `google-services.json`, заменить им файл в корне репозитория (или
   прислать — заменит ассистент).
3. Ключ сервисного аккаунта: Firebase → Настройки проекта → Cloud Messaging →
   Firebase Cloud Messaging API (V1) → создать ключ. Загрузить в EAS:
   `eas credentials` → Android → Google Service Account → FCM V1.

### 2. Новый проект EAS (чтобы развести старое и новое приложения)
1. `eas init` в папке проекта. EAS создаст проект и выдаст `projectId`.
2. Прислать `projectId` — ассистент поменяет `app.json`: `slug`,
   `extra.eas.projectId`, `updates.url`, `owner`.
3. Если выдан новый токен EAS — обновить секрет `EXPO_TOKEN` в GitHub.

### 3. Секреты и переменные

| Имя | Где | Нужно для |
|---|---|---|
| `EXPO_PUBLIC_APP_SECRET` | GitHub Secrets | **обязателен**: ключ приложения для сервера; без него сборка не стартует |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | GitHub Secrets | обязателен для сборки (ключ собственного сервера jobtoo.ru; облачный Supabase удалён и не нужен) |
| `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SUPABASE_URL` | GitHub Secrets | адреса сервера (обычно `https://jobtoo.ru`) |
| `EXPO_PUBLIC_APPMETRICA_API_KEY` | GitHub Secrets | необязателен: ключ AppMetrica; пуст — отчёты о падениях выключены |
| `EXPO_PUBLIC_YANDEX_MAPS_KEY` | GitHub Secrets | необязателен |
| `EXPO_TOKEN` | GitHub Secrets | сборка и обновления по воздуху |

Ключ AppMetrica: appmetrica.yandex.ru → «Добавить приложение», пакет
`com.jobtoo` → скопировать ключ в секрет. Политика и Согласие уже дополнены
(редакция 2026-10-03). Ключ нужно положить в оба конвейера: сборки и
обновлений — они читают один и тот же секрет.

### 4. Пробная сборка и проверка на телефоне
1. GitHub → Actions → **EAS Build** → Run workflow (Android) или тег `build-…`.
   Сборка идёт на серверах EAS; готовый APK — на expo.dev, раздел проекта.
2. Установить APK на телефон. Пройти список ниже. Что сломалось — описать
   ассистенту (экран, что сделали, что увидели).

**Что проверить (особенно жесты и ленту: Reanimated 4 и новая архитектура на
устройстве не запускались ни разу):**

- [ ] Запуск без падений, заставка, онбординг (три слайда, крестик).
- [ ] Регистрация по почте с кодом; вход; выход.
- [ ] Окно согласия (Политика, Соглашение): принять; в Соглашении есть п. 3.1.1 (18+).
- [ ] Ссылка `https://jobtoo.ru/` из сообщения открывает приложение (после шага 6).
- [ ] Лента: карточки листаются, свайп вправо и влево, откат, фильтры.
- [ ] Отклик: свайп вправо запускает Юпитера, статус виден в «Откликах».
- [ ] Лимит 10 откликов: после десятого лента показывает «На сегодня всё».
- [ ] Вкладка «Отклики»; «Почта JobToo»; вопросы работодателя.
- [ ] Профиль: загрузка PDF-резюме, фото профиля, редактирование.
- [ ] Чат: текст, фото, голосовое сообщение (запрос микрофона).
- [ ] Уведомления: включить, получить тестовое (нужен шаг 1).
- [ ] Удаление аккаунта работает.

### 5. Ключ подписи
После первой сборки EAS создаёт ключ подписи Android. Скачать и сохранить в
надёжном месте: `eas credentials` → Android → Keystore → скачать. **Потеряете
ключ — обновить приложение в магазине будет нельзя.** Прислать ассистенту
отпечаток SHA-256 (`eas credentials` покажет).

### 6. Ссылки jobtoo.ru открывают приложение
Решено 03.10.2026. В `app.json` добавлены `intentFilters` (Android App Links,
`autoVerify`): корень `https://jobtoo.ru/` и экраны `/ext-vacancy`,
`/perm-vacancy-detail`, `/invite`, `/reset-password`, `/login`, `/register-worker`,
`/legal`, `/mail`, `/jupiter-application`, `/jupiter-captcha`, `/jupiter-questions`.
Служебные адреса (`/api`, `/.well-known`, карта сайта и т. п.) не перехватываются.
Ссылка откроется в приложении, когда Android проверит принадлежность сайта:
для этого отпечаток SHA-256 из шага 5 уже внесён (03.10.2026) в блок `com.jobtoo` файла
`public/.well-known/assetlinks.json` (блок старого
приложения `com.nikidav23.onspaceapp` остаётся, пока оно живо). Пока файла с
отпечатком нет, ссылки открываются в браузере — ничего не ломается. Проверка
на телефоне: открыть `https://jobtoo.ru/` из сообщения — должно открыться
приложение. В `apple-app-site-association` стоит `TEAMID` — для iPhone не
нужен, пока приложения нет в App Store.

## После выхода приложения

Пока старое приложение 1.4.0 живо, сервер сохраняет для него совместимость.
Когда новое приложение вышло и старое снято, можно убрать:

- регистрацию по телефону и паролю в `dbUpsertUser` (`php-proxy/db.php`, ветка
  «Телефон с паролем принимаем только от старых сборок») и клиентские ветки
  `emailAuthReady` в регистрации и входе;
- таблицы и функции смен: `jm_vacancies`, `jm_bulletins`, `jm_likes`,
  `jm_worker_slots`, `jm_saved`, `jm_vacancy_views` и заглушки `dbUpsertVacancy*`
  (отвечают 410);
- отдельная заметка владельцу: в старом приложении нет заголовка версии, поэтому
  показать его пользователям «установите новое приложение» можно только
  серверным текстом ошибки на регистрации и входе (по отсутствию заголовка
  `X-App-Version` у запросов из приложения). Это отдельная доработка, делать
  её имеет смысл после публикации нового приложения.

## Чего менять нельзя после выхода (кроме новой сборки)

- `version` в `app.json`: при `runtimeVersion: {policy: "appVersion"}` новая
  версия отрезает обновления по воздуху от уже установленных сборок.
- Нативные модули: их нет в собранном бинарнике, обновление с ними упадёт.
- Пакет `com.jobtoo` и ключ подписи.
- Минимальная версия приложения для сервера — меняется только на сервере
  (`JT_MIN_APP_VERSION`), клиент трогать не надо.
