# Карьерные источники: прогон 16.09.2026

Задача владельца: довести карьерные сайты до рабочего состояния — не
зарегистрировать 170 адресов, а реально получать вакансии и убедиться, что
каждая ведёт на живую страницу работодателя.

## Числа

| | Было утром | Стало |
|---|---|---|
| Находок разведки | 12 из 170 | **74 из 170** |
| Подтверждено проверкой | не проверялось | **66** |
| Уходит в источник | — | **46 + Детский мир** |
| Компаний в ленте на проде | 19 | считаем после выкатки |
| Вакансий в ленте на проде | 824 | считаем после выкатки |

## Почему находок стало в шесть раз больше

Разведка искала вакансии **только в JSON-ответах**. Самый частый случай —
сайт отдаёт готовый HTML со ссылками на вакансии, никакого API нет — она не
видела вовсе. 60 находок из 74 пришли именно оттуда.

Правило поиска пути описано в `pickLinkPattern`. Первая версия считала хвосты,
и проверка это поймала: под `/career/` лежат те же вакансии плюс «о нас», то
есть хвостов у короткого пути всегда больше, и побеждал он. Решают чистота
(доля ссылок с человеческим заголовком) и листовость (у вакансии хвост — один
сегмент).

## Три отсева

**Проверялка** (`scripts/career-endpoint-verify.mjs`) читает находку тем же
способом, каким читает прод: обычным запросом без браузера. Три условия, и все
обязательны — адрес отдаёт список; ссылка на вакансию открывается; выдуманный
адрес ту же вакансию не показывает.

**Путь ссылки** (`vacancyLinkPath`). Проверялка смотрит, что ссылка
открывается, но раздел «Услуги» открывается ничуть не хуже вакансии. Смотрим
последний сегмент пути, а не путь целиком: `/jobs/hiring-events/` содержит
«job», но ведёт на события. Так отброшено 20 находок.

**Сверка по URL в самой миграции.** Часть источников уже стоит в настройке;
проверка «есть ли первый» либо пропустила бы всю пачку, либо задвоила половину.

## Отдельно: карантин

В `scripts/career-runtime-quarantine.json` лежат 17 адресов, забракованных
полным проходом **с production-сервера**: 403, 404, 405, 477. Из этой сессии
15 из 17 отвечают 200 с настоящими данными. Разница не в заголовках — с тем же
User-Agent, что у прода, они тоже отвечают 200. Значит дело в адресе, с
которого приходит запрос.

Проверять это надо С ПРОДА, а не отсюда, — и новые адреса, найденные разведкой,
как раз другие: у Wildberries `crm-api/api/v1`, а в карантине `hr-crm-api/api/v2`;
у CDEK и Cloud.ru вместо JSON теперь ссылки в разметке. Карантин сверяет точный
URL, поэтому новые находки он не блокирует, и следующий полный проход покажет,
отвечают ли они production-серверу.

## Второй заход по рознице: терпение не помогло

44 сайта розницы, логистики и общепита — Магнит, Лента, Чижик, ДИКСИ,
Монетка, SPAR, DNS, Деловые Линии, ПЭК, Почта России, Додо, Burger King,
Теремок, Самокат, Спортмастер, Ozon, Сбер, Росатом — прогнаны второй раз с
вдвое большим ожиданием, вдвое большим числом нажатий и долгим доскроллом.
**Результат: ноль новых.** Единственный «готов» — М.Видео, который и так уже
подключён.

Это важный отрицательный результат: дело не в нетерпеливости разведки. Что
видно по сырым ответам:

| Сайт | Что отвечает нашему запросу |
|---|---|
| Магнит | 200, но 3,7 КБ — пустая оболочка, ссылок нет |
| Монетка | 1,2 МБ разметки и ни одной ссылки на вакансию |
| Чижик | 403 |
| Деловые Линии | 401 |
| Почта России | 417 |
| Теремок | 404 на адресе из списка |
| Лента | соединение не устанавливается |

То есть три разные причины, и ни одна не лечится настройками разведки: либо
данные приходят из API, который надо найти поимённо, либо сайт закрыт, либо
адрес в списке устарел. Дальше — только поштучная работа по каждому.
