# Задание: научить карьерный коннектор читать сайты работодателей

Составлено 15.09.2026 после разбора конкурентов. Это постановка для Codex —
в ней всё, что нужно, чтобы начать без переписки и без повторной разведки.

## Зачем это делается

15.09 владелец сменил модель сервиса. JobToo — платформа из двух разделов:
«Подработка» (смены линейного персонала) и «Работа» (постоянные вакансии
компаний, включая IT и крупный бизнес). Из агрегаторов остался **один партнёр,
Arbihunter**; SuperJob и hh.ru выключены миграцией
`072_only_arbihunter_and_career.sql`.

Последствие прямое: поток чужих вакансий упал до каталога Arbihunter — на 15.09
это 303 вакансии — плюс свои. Заменить объём должны официальные карьерные
страницы работодателей. Сегодня они не читаются вовсе, и это задача.

## Что уже проверено — перепроверять не надо

Всё ниже добыто живыми запросами 15.09, подробности и цифры в
`docs/источники-вакансий-разбор.md`.

1. **`php-proxy/career_feed.php` умеет читать только разметку
   `schema.org/JobPosting`.** Других форматов он не знает.
2. **Разметки нет ни у кого из проверенных.** Ни у складских работодателей
   (Самокат, X5, Магнит, ВкусВилл, Детский мир, Яндекс Еда), ни у крупных IT
   (Сбер, МТС, Росатом, Яндекс, Ozon, ВТБ, Т-Банк, VK, Ростелеком, Yadro,
   МегаФон, Золотое Яблоко). Проверено по странице списка вакансий каждого.
   То есть коннектор не сломан — читать на этих страницах нечего.
3. **У конкурента cofinder.ru открытый API без ключа**, и в нём лежит готовый
   список карьерных сайтов: `GET https://cofinder.ru/api/v1/companies/?limit=500`
   отдаёт 160 компаний с полем `career_url`, из них 111 российских. Полный
   список продублирован таблицей в конце `docs/источники-вакансий-разбор.md`.
4. **Цена подхода «парсер под каждый сайт» известна.** В том же ответе cofinder
   отдаёт своё поле `parse_status`: 15 парсеров из 111 сломаны. Причины —
   перевёрстанный сайт, просроченный сертификат, а у Альфа-Банка в сообщении
   лежит Selenium stacktrace, то есть ради части сайтов они гоняют браузер.

## Главная мысль задания

**Искать за сайтом его собственный API, а не разбирать HTML.**

Большинство карьерных сайтов — SPA: страница приходит пустой, вакансии
подгружает скрипт. Значит за ней всегда стоит источник данных, и он отдаёт
структурированный JSON. Это подтверждено дважды, и оба раза найдено перебором
за минуты:

- у cofinder — `/api/v1/vacancies/?limit=100&offset=N` (FastAPI, `total` 18 001);
- у карьерных сайтов на Хантфлоу — `https://<компания>.huntflow.io/api/vacancy`
  отдаёт список, `/api/vacancy/<slug>` — полное описание (`intro`, `body`,
  `conditions`, `requirements`). Проверено на пяти разных клиентах платформы,
  структура одинаковая.

JSON лучше HTML по двум причинам: он не ломается от редизайна и это штатный
интерфейс сайта, а не разбор чужой вёрстки.

## Что сделать

### Этап 1. Разведка, и она важнее кода

Пройти карьерные сайты и для каждого записать, чем его можно читать. Брать
из двух списков: российские компании из таблицы в
`docs/источники-вакансий-разбор.md` и работодатели линейного персонала (Ozon,
Wildberries, Самокат, X5, Магнит, Лента, ВкусВилл, СберМаркет, Яндекс Лавка).

По каждому ответить на четыре вопроса:

| Что выяснить | Как |
|---|---|
| Есть ли JSON API | открыть страницу вакансий, посмотреть запросы; перебрать `/api/vacancy`, `/api/v1/vacancies/`, `/wp-json/wp/v2/*` |
| Есть ли разметка | `curl` страницы, искать `JobPosting` и `application/ld+json` |
| Что говорит `robots.txt` | у всех проверенных вакансии разрешены; исключения фиксировать |
| Есть ли там наши вакансии | смены и линейный персонал, или только офис |

Результат этапа — таблица в `docs/источники-вакансий-разбор.md`: сайт, способ
чтения, адрес эндпоинта, что отдаёт. **Без этой таблицы к этапу 2 не
приступать**: писать коннектор вслепую — это повторить 160 парсеров cofinder.

### Этап 2. Второй способ чтения в коннекторе

Научить `php-proxy/career_feed.php` читать не только `JobPosting`, но и JSON по
описанию из настройки источника. Сегодня адреса страниц лежат в
`connector_config.pages` источника `career` (`php-proxy/career.php` их читает);
рядом должно появиться описание, откуда и как брать JSON: адрес эндпоинта и
соответствие полей нашему формату (`docs/feed-format.md`).

Требования:

- **Правила безопасности не ослаблять.** `career.php` уже ходит только по
  публичному HTTPS через `ing_safe_https_url`/`ing_safe_https_resolve`, не идёт
  по редиректам, закрепляет IP и держит предел размера ответа. Всё это остаётся
  и для JSON.
- **Ссылка на первоисточник обязательна.** В `cf_normalize` стоит правило: нет
  ссылки — вакансию не берём. Оно не обсуждается: этим мы отличаемся от
  swipejobs, который выдаёт чужие вакансии за свои.
- **Чистые функции отдельно от сети.** Разбор — в `career_feed.php`, сеть — в
  `career.php`. Так уже устроено, сохранить.

### Этап 3. Раздел определяет правила приёма

Знать про `php-proxy/ingest.php`: профессия (`work_type`) обязательна **только**
для `kind = shift`. Для постоянных вакансий она может быть пустой — иначе
отсев выбросит весь раздел «Работа». Карьерные вакансии должны приходить с
`kind = 'permanent'`, как это уже делает `career_feed.php`.

## Признак готовности

1. В `docs/источники-вакансий-разбор.md` есть таблица разведки по всем
   проверенным сайтам.
2. Источник `career` с вписанными адресами возвращает непустой список вакансий
   хотя бы от одного работодателя, и вакансия доходит до базы.
3. Есть проверка на разбор нового формата, и она падает, если формат сломать.

## Чем проверить

- `php -l` по всем изменённым файлам.
- Все `tests/*_test.php` и `tests/*_test.py` — полный прогон, не только свои.
- Мутация: сломать разбор нового формата и убедиться, что проверка краснеет.
  Проверка, зеленеющая на сломанном коде, хуже отсутствующей — в этом проекте
  такое уже случалось дважды.
- Источник в панели включать только после того, как глазами посмотрели, что
  именно он отдаёт. Так заводили hh миграцией `058`.

## Чего делать нельзя

- **Не гонять браузер.** Selenium и headless Chrome ради вакансий — это
  отдельная инфраструктура, которая ломается и стоит денег. Если сайт читается
  только браузером, записать его в таблицу как «не берём» и идти дальше.
- **Не писать парсер под каждый сайт.** Если у сайта нет ни API, ни разметки —
  он не наш кандидат. Пятнадцать сломанных парсеров у cofinder показывают, чем
  это кончается.
- **Не копировать список компаний cofinder как источник вакансий.** Проверено:
  наших профессий там нет — комплектовщик 0, упаковщик 0, а категория
  «Logistics / Supply Chain» пуста. Список полезен как перечень адресов
  карьерных сайтов, не более.
- **Не включать источник, не посмотрев его выдачу.**
- **Не трогать выключенные источники.** `superjob`, `headhunter`
  выключены решением владельца, а не по ошибке.
