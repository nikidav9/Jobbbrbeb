# Почта Jupiter

Для отклика требуется выбранный PDF в сейфе резюме. На карьерном сайте
указывается персональный адрес вида `имя.фамилия@jobtoo.ru` (с 25.09.2026;
раньше — `u-<случайный токен>@`, такие адреса удалены миграцией 110). Выдаёт
его `jt_jupiter_mailbox()` в `php-proxy/db.php` по правилам из
`php-proxy/jupiter_mail_address.php`: латиница, при повторе цифра
(`ivan.petrov2`), служебные имена (`support`, `admin`…) не выдаются, адрес
удалённого аккаунта (`jm_jupiter_retired_addresses`) повторно не выдаётся.
Адрес закрепляется навсегда: смена имени в профиле его не меняет.
Ответы должны попадать в раздел «Почта JobToo».

`jobtoo.ru` уже принимает почту через MX Timeweb. Для входящих писем нужен
`support@jobtoo.ru`, выбранный в панели как сборщик писем для домена. В серверном файле `/opt/jobtoo-secrets/env`
задаются `JUPITER_MAIL_IMAP_USER` (полный адрес этого ящика) и
`JUPITER_MAIL_IMAP_PASSWORD`; сервер создаёт и запускает `jt-jupiter-mail`.
Он читает IMAP Timeweb и сохраняет письма через закрытый API. Timeweb при
catch-all доставке сохраняет исходного envelope-recipient в собственном
`Received`-заголовке на публичном MX (`by mxN.timeweb.ru ... for ...`). Jupiter
доверяет только первому такому hop сверху и не маршрутизирует по `To`, `Cc`,
`X-Original-To` или `Envelope-To`, потому что эти поля может прислать отправитель.

Перед разрешением реальной отправки необходимо проверить доставку на
новый персональный адрес: найти письмо в `support@jobtoo.ru`, убедиться,
что первый `Received`-hop, добавленный публичным MX Timeweb, содержит исходный
адрес `u-...@jobtoo.ru` в `for ...`, а входящие появляются в правильном аккаунте.
Проверить также письмо с подложными `To`, `X-Original-To`, `Envelope-To` и
`Received`, чтобы чужие письма не попадали кандидату. Если публичный MX перестанет
сохранять проверяемый envelope recipient, оставлять флаг выключенным.
Только после успешного сквозного теста задать `JUPITER_MAIL_VERIFIED=1`
в секретах и перезапустить PHP и `jt-jupiter`.

В исходном интерфейсе Sorce есть личный адрес `@sorce.email` и входящие,
но внутренний способ доставки по скриншоту определить нельзя. Timeweb
разрешает catch-all и IMAP. SMTP Timeweb требует, чтобы адрес отправителя
совпадал с учётной записью; для ответа *с персонального адреса* потребуется
отдельная отправка от созданного ящика или другой почтовый провайдер.
Текущий экран показывает входящие; отправка писем из интерфейса не включена.
